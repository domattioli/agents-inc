# CONTEXT.md — glossary

Canonical terms for agents_for_dummies. Glossary only; no implementation detail.

## Canonical term table

One name per thing (D83). Two axes plus one relation: role (CEO, CoS, Lead, Worker), rung (Executive, Orchestrator, Workhorse, Grunt) and relation (delegate, supervisor). Write "operator" in prose for the human; write "CEO" only when naming the chain position (chain figure, role table, the CEO entry, the pair "CEO and CoS"). `lint` aliases are caught by `tools/check_terms.py`; `review-only` aliases are caught in review.

| Term | Axis | Definition | Retired aliases (check) |
|---|---|---|---|
| CEO | role (human) | The chain position held by the operator; fixed noun with CoS (D46.4). | Owner (lint) |
| operator | human | The human who owns the work and rules on decisions. The prose name for the CEO. | user in the role sense (review-only) |
| Chief of Staff (CoS) | role | The agent the operator talks to. Only dispatcher of the top-level Lead, verifies every report before relay, only committer and pusher (D43, D46). | Interlocutor (lint); Driver (lint; plain-English "driver" unaffected) |
| Lead | role | The one agent the CoS dispatches for a mandate (a nested Lead, D51, is dispatched by a Lead); runs the mandate, may dispatch Workers within FAN_OUT and depth rules, reports once at mandate end (D46, D48). | Orchestrator as a Lead alias (lint) |
| Worker | role | An agent dispatched by a Lead that reports to that Lead (D46). | Workhorse, Grunt as Worker aliases (lint); Team as Worker collective (review-only); Delegate as Worker alias (review-only) |
| Delegate | relation | Any agent reached by dispatch. Usually a Lead or Worker; a D78 native small-edit subagent is a delegate with neither role. Not a Guest agent or consult. | none |
| supervisor | relation | Lowercase. The party that dispatched a given delegate and verifies its return: the CoS or a Lead. Never a title, rung or role. | Supervisor (capitalized: former Lead alias and Orchestrator-rung synonym) (lint); Dispatcher in the relational sense (review-only); "one rung up" as a chain step (lint) |
| Executive | rung | Top model class (fable, astra). Default duty judgment only (D78.2, D80). | frontier as a rung name, ultra-tier (lint) |
| Orchestrator | rung | Second class (opus, sol). Default duty design and scope judgment, review, gates (D78.1). | none |
| Workhorse | rung | Third class (sonnet, terra). Default writer (D78.1). | none |
| Grunt | rung | Fourth class (haiku, luna). Read-only by default (D78.1). | cheap as a rung name, flash-tier (lint) |
| Rung | rung | A model class. Sets ladder order for Lead choice, delegation rights and default duties; never grants Task Authority or special access. | Tier as a rung noun, mid as a rung name (lint) |
| Family | other | One dispatching node and every node below it (D27). Short form "fam" is kept. | none |
| Team | other | Proposed (D63): one session and the delegates and Syncs it started. | none (the Worker-collective sense is retired in the Worker row) |
| Chief | other | Proposed (D63): live-view label for a team's CoS. Not a new role. | none |
| Guest agent | other | An operator-started agent outside the reporting chain. | none |
| Host | other | The agent CLI the user runs (Claude Code, Codex). | none |
| Stdin worker | other | MVP adapter path: a model call that reads stdin and returns a candidate, no tools. | none |

## Glossary

| Term | Meaning |
|---|---|
| **Host** | The agent CLI the user runs. Launch hosts: Claude Code and Codex. |
| **Stdin worker** | MVP adapter path only: a model invocation that receives text on stdin and returns a candidate. No tools. |
| **Worker** | An agent dispatched by a Lead that reports to that Lead (D46). Not every delegate is a Worker: a native small-edit subagent (D78) reports to the CoS and has no Lead. |
| **Delegate** | Relation, not a role: any agent reached by dispatch. Usually a Lead or a Worker; a D78 native small-edit subagent is a delegate with neither role. Not a Guest agent or a consulted model. |
| **supervisor** | Lowercase, a relation and never a title: the party that dispatched a given delegate and verifies its return, the CoS or a Lead. The rendered `SUPERVISOR` prompt slot names it. For a nested Lead (D51) it is the dispatching Lead. |
| **Reviewer** | A model invocation, from a different vendor than the stdin worker, that checks consequential claims against original sources. |
| **Verifier** | Deterministic code checks (quotes, hashes, anchors, arithmetic). Not a model. |
| **Required provider** | Claude Code only. Subscription login. Codex is optional since 2026-10-03; making Claude optional too is deferred to v1.0. |
| **Optional provider** | Gemini, Mistral, OpenRouter free tiers. API key. Missing key skips the provider, never blocks setup. |
| **Free** | Zero incremental dollars per task. Subscription-included or free-tier API key. |
| **Spend cap** | Hard $0 per task. Quota exhaustion pauses the job and tells the user. No paid API path exists. |
| **Workspace authorization** | Explicit per-workspace grant permitting confidential inputs to reach optional providers. Default: denied. |
| **Returned** | Stdin worker process exited 0 and produced output. Says nothing about correctness. |
| **Verified** | Returned output passed verifier and reviewer gates. |
| **Needs-review** | Verified checks passed but an unresolved critical issue remains for a human. |
| **Accepted task** | A task whose output reached verified or needs-review with a retained draft. Unit of the cost metric. |
| **Cost metric** | Dollars per accepted task, measured against an all-frontier baseline, with a quality floor of zero false accepts on seeded faults. |
| **Mode** | lawyer / scientist / engineer. Changes required fields and forbidden actions, never data policy. |
| **Acceptance user** | Tim (lawyer, documents to cited brief) and Dom (engineer/scientist tasks). Both day 1. |
| **Node** | One delegated job recorded in the dispatch graph ledger; identity = id; carries model, tier, task, provider, parent_id, edge_type, status, seconds, subscription_calls, gate_reason, timestamp. |
| **Edge** | Directed relationship in dispatch graph, implied by child node's parent_id + edge_type (not separately stored); types: reviews, corrects, probes, depends-on, seconds. |
| **Run** | Groups of nodes from one brief or one doctor preflight (identified by run_id); groups all worker, reviewer, and correction nodes for one top-level invocation. |
| **Run tree** | The nodes of one run arranged as a single rooted tree. Root = the orchestrating act that received the ask; every other node descends from it via parent_id. Chosen over a forest (operator, 2026-09-06) so fan-outs can be planned and read as one structure. |
| **Family** | One dispatching node plus every node descending from it; an agent that dispatches children roots a family tree. The run tree is the top family; families nest. Alias: fam. Synonym retired: delegation (one parent→child edge). Fan-out now means the D48 Worker budget (see Fan-out). |
| **Orchestrator** | A rung: the second model class (opus, sol). Default duty is design and scope judgment, review and gates (D78). A rung only, never a role; the role that manages a run is Lead. |
| **Lead** | The top-ranked model the operator named for a run; manages the run, owns the mandate, reports to the CoS once at mandate end; Task Authority only when policy grants it; an Executive-rung model has no automatic final say (D46). May dispatch Workers by rung (D46.3); depth rules count from the dispatching Lead. Width and total per D48. |
| **Fan-out** | Per D48: Worker budget per dispatch (width at once, total per mandate, depth below Lead); rung defaults, verify cap floor(20/f), roster floor 1, report `WORKERS SPAWNED: n`. Old sense (the act of dispatching children) is retired in favor of "orchestration" (D46). |
| **Chief of Staff** | The only agent that dispatches the Lead, verifies every report before relay, and commits or pushes (D43, D46). The operator's right hand; alias **CoS**. The agent the operator talks to directly, normally the host session. Reads and routes dispatches, verifies claims before relaying, sorts the Lead's report into DECIDE (irreversible, costly, externally visible, scope-changing), HANDLED (CoS decided itself), and UNDERSTAND (operator needs context). Answers 3-tool lookups itself; every repository edit goes through a delegate: a native workhorse subagent for an edit of 3 tool calls or fewer, `agents-inc dispatch` for anything larger (D78). On the Executive rung it keeps judgment only (D78). Never relays raw reports. No automatic Task Authority over the Lead's work. Charter: `docs/governance/DELEGATION-MODEL.md`. |
| **Mandate** | One Lead's task, roster, gates, snapshot, and report contract. Ends when the Lead reports (D46). |
| **Guest agent** | A model from any provider that the operator starts through the Agent tool, opens as a transcript in the primary view, and messages, the same as a Claude subagent. Sits outside the reporting chain: not dispatched, reports to no Lead. Not a Worker or delegate: those are reached by dispatch. Fixed 2026-11-11 (operator). |
| **Turn** | One run of a delegate from its prompt to its report. A dispatch is the first turn; each resume adds one turn in the same session. No message reaches a delegate during a turn (D54). |
| **Resume** | One more turn for a finished delegate in its own Claude session or Codex thread: `agents-inc dispatch --resume <run> --message <text>`, or the broker `resume` tool with new id `<id>-r<n>`. Cap 1 for Grunt, 2 for Workhorse and above; never counts as a new Worker (D54). |
| **Question** | A running broker Worker's `ask_lead` call. The broker screens it and relays it to the Lead as status `needs-lead`; the Lead replies with `answer`. The Worker waits up to 30 minutes, then decides or stops (D54). |
| **Lost run** | A dispatch run that has no outcome and has written nothing new for 5 minutes. The delegate pane shows it as an alert that needs acknowledgement. It stops being lost when it writes again or records an outcome. |
| **Home repo** | The repository that holds a consumer's agent-only artifacts (specs, run specs, teach-me, introspect, grill notes). DomI for this operator; other consumers name theirs in AGENTS.md (D46). |
| **CEO** | The chain position held by the operator. Fixed noun with CoS (D46). Prose says operator. |
| **operator** | The human who owns the work and rules on decisions; the prose name for the person in the CEO chain position. |
| **Second** | An agent that helps a run. It has no automatic authority from being second, vendor, or rung. Any Task Authority must come from policy and be recorded. Structurally it may be a child with edge type `seconds`; graph shape does not grant authority. Retired as a role (D46); name the function instead: reviewer or backup. |
| **Task Authority** | A policy-granted role with final say on one task, inside recorded limits. It may accept, reject, or ask for revision. It cannot break policy, grow scope, or approve blind. An untrusted free model can never hold it. |
| **Capability Escalation** | Send the same task to a stronger allowed model. Task Authority stays with its holder, but only if that holder can judge the result. |
| **Authority Reassignment** | An explicit, recorded move of Task Authority to a pre-approved new holder. Use it when the old holder cannot continue or cannot judge the work. |
| **Promotion** | Retired for new decisions. Use Capability Escalation and/or Authority Reassignment. Old D27 uses remain historical record. |
| **Rung** | A model class: Executive, Orchestrator, Workhorse, Grunt. A rung decides ladder order for Lead choice (D46.2), delegation rights (D46.3) and default duties (D78 as overridden by D80): Workhorse writes, Orchestrator judges and reviews, Grunt (haiku, luna) may write when authorized for the task, Executive keeps judgment only. A rung, vendor, or pair never grants Task Authority or special access. Policy chooses allowed models from any vendor's whole model list. Renamed 2026-09-07 (D34): the old top rung name became Executive; D83 retired the `Supervisor` synonym of Orchestrator. Ranking table of record: docs/governance/ROUTING-RANKING.md. |
| **Second opinion** | The same task sent to the paired model without the first answer. The supervisor compares both outputs afterward. Tests independent reasoning; never asks one model to approve another's conclusion. |
| **Advisor / @model** | Two review paths outside dispatch. Claude Code `/advisor`: a Claude model that reads the working model's full context mid-turn; not blind, not recorded. `@model` router (`skills/codex-bridge/scripts/at_route.sh`, `docs/at-route/AT-ROUTE.md`): operator-typed question to one alias, see Consult, logged only to `~/.codex-bridge/`. Neither is a Second opinion, holds Task Authority, or writes a ledger node. |
| **Consult** | Proposed (D63, not yet accepted). Family name for advice-only calls. Read-only tools; no mandate, Lead, gates, Task Authority, or ledger node. A consulted model or thread is not a delegate. Forms: Sidebar, Sync, Follow-up. D63 proposes its own cap; until D63 is accepted, `@@` Codex threads use the D54 cap (D62). An operator `@<handle>` to a finished Worker forks it and never resumes it. Old name: "side question". |
| **Sidebar** | Proposed (D63). `@a q`. The answer is shown to the operator only, and the session model does not run, except in two cases: `AT_ROUTE_MODE=relay`, and a failed or timed-out delegate call, where `at_route.sh` hands the question to the session model. The call is logged. |
| **Sync** | `@@a q`. The answer enters session context. One long-lived thread per alias: for Claude, the background session `at-<alias>`; for Codex, planned (D62 PR A) as the thread keyed by cwd, session, and alias; today one fresh run per question. For a Codex sync, `@@a /new` ends it (D62); `at_route.sh` rejects slash commands for Claude aliases, so ending a Claude sync is open (D63, proposed). |
| **Follow-up** | Proposed (D63). `@a! q`. An async job; the session model does not run. The answer lands in the In-tray (D63). |
| **In-tray** | Proposed (D63). `@inbox`. Shows each finished Follow-up once (D63). |
| **Memo** | Proposed (D63). A one-way note to a running Worker, `@<handle>! note`. The Worker reads it at a checkpoint. A Codex memo lands on the next resume, and the pane marks it pending. Senders are the operator and the CoS (D63). |
| **Handle** | Proposed (D63). The name of a delegate, alias-greekletter (`luna-beta`), with no team part. Unique within its session; a letter is reused only after its run leaves the view, which is when its session ends. The detail row shows the full run id. `@<handle> q` is a Sidebar and `@@<handle> q` is a Sync with that Worker (D63). |
| **Stand-up** | Proposed `@standup`. Each live delegate and Sync gives one status line, built from events and the pointer registry, at no model cost (D63). |
| **Floor** | Proposed (D63). One project (repo root) in the live view. The building side view lists every floor with its live count; a click opens its 2D floor plan. An elevator view is the second way in (D63). |
| **Team** | Proposed (D63). One session, under any harness, and the delegates and Syncs it started. Its color is a stable hash of the session id. The view shows a team letter as a badge next to each handle; the letter is not part of the handle. |
| **Chief** | Proposed (D63). The live view's name for a team's session model; it gets the chief's office. In canon it stays the CoS of its own session, so two teams on one floor are two chiefs reporting to one operator (D63). |
| **Free grunt** | Any GPT model outside the ladder (gpt-5.4-mini included), every OpenRouter free model, Gemini free tier, Mistral free tier. $0 only. Never a Codex subscription call. In budget modality free grunts fill workhorse and grunt slots and review each other across upstream vendors. Coding permission is scoped: well-scoped, small jobs only — high volume of small diffs, never a large or architecturally significant change (AGENTS.md Project rules). |
| **Run spec** | Saved routing input for one run: task and pass rule; Task Authority and limits; authority-move rule; policy version; allowed models; hard limits; budget and deadline; ranking order; retry and fallback rule. Missing ranking order makes the run invalid. |
| **Derivation** | From a saved run spec and model-list snapshot: remove hard-limit failures; rank kept candidates by the stated order; break ties by model ID. Save every candidate and keep/drop reason, the pick, snapshot ref, retries, and every Authority Reassignment. This gives policy-choice determinism and replay, not deterministic model output or live availability. |
| **Modality** | Ideal or budget. Ideal = the full derived tree. Budget = same spec and shape, but workhorse and grunt slots filled by free grunts through OpenRouter, ladder models kept for the Executive and Orchestrator rungs, review, and fallback. |
| **Scout** | A cheap, bounded reconnaissance dispatch sent *before* committing real work, to answer a feasibility or existence question: does X exist, what shape is it, is it worth a real dispatch. Produces a finding, never a deliverable: a scout may not write to the repo, and its report is unverified by construction (same bar as any delegate report). Whoever acts on a scout finding re-derives it. Scouting is a mode of dispatch, not a rung. |
| **Scout node** | The ledger record of a scout. Carries edge type `probes`, the same type already used for doctor preflight probes (`parent_id` None, projected through `legacy_parent`). A scout never becomes a spawn parent: it takes no `lineage` row, so recon is auditable in the run without appearing as an ancestor of the work it informed. |
| **Scout roster** | Who may scout. Default: free grunts (OpenRouter free, Gemini free, Mistral free, gpt-5.4-mini) — text-in/text-out recon over a supplied blob. When the recon needs tools (walk a repo, read a tree, run a command) it goes to the Grunt rung, haiku or luna, because free grunts have no tools. Never Workhorse rung or above: recon that needs sonnet/terra is not recon, it is the work, and belongs in a real run spec. Sole exception is a Lead assignment with a recorded gate reason (D27 promotion (c)). |
| **Handoff lint** | Deterministic lint-and-reject pass over one model-to-model message (dispatch prompt down, delegate report up), run before send and before acting on a report. Six mechanical rules: social padding, provenance tags on claims (`[verified]`/`[inferred]`/`[assumed]`), dangling references with no in-message antecedent, task-contract fields (goal, constraints, done, out of scope), duplicated blocks, paraphrased errors. Never rewrites the message; never touches hedges or reasoning. Tool of record: optional user-scope third-party `handoff-lint` (D41); absent → `handoff-lint NOT installed -> H1-H6 checked by hand` (D42). Complements, does not replace, the 14-element delegation prompt contract. |
| **Budget review** | In budget modality a free grunt is reviewed by a free grunt from a different upstream vendor (OpenRouter, Gemini, Mistral pooled). Deterministic pick from the catalog's upstream-vendor field. Quota-paused reviewer falls back to the ladder grunt (haiku or luna). |
| **Finding** | Lint result from dispatch graph ledger; carries rule (depth, same_vendor_review, frontier_without_gate), node_ids, and human-readable message. |
| **Ledger** | Append-only JSONL file (`<workspace>/.workerbees/ledger.jsonl`) recording every delegated job as a node; idempotent by node id on read (dedup merges dispatch + return records). |
| **Agent** | Registered identity in the governance graph; carries id, name, type, capabilities, clearance, enabled flag. Model id is not an agent id. |
| **Capability** | A named operation an agent may perform (e.g. `extract.markdown`, `review.claims`). Unsupported ones — deploy, delete, send, grant, tools, web — are registered as disabled and always denied. |
| **Relationship** | Directed edge between two agents (`delegates_to`, `requests`, `probes`) with allowed params. Policy maps a `request` envelope to `delegates_to`; absent edge denies. |
| **Decision** | Verdict of one policy evaluation: allowed, decision_id, reason_code, reason, policy_version, checked_rules. Persisted before dispatch, for denials as well as allows. Never carries prompts, output, or secrets. |
| **Gateway** | The single dispatch boundary. Validates the envelope, authorizes it, reserves budget, invokes the adapter, records the decision and the ledger node, releases in `finally`. Permission from the gateway is never a claim about output quality. |
| **Tool access** | D49. Codex shell tool on by default for astra/sol/terra under `agents-inc run`; off for luna, raw slugs, free providers; `--no-tools` forces off. Codex permission profile, no `-s` (a `-s` override silently replaces it): read cwd, system, /opt/homebrew, /tmp; rest of HOME unreadable; writes only with `--write` (cwd); network off. Live-proved 2026-10-04. |
| **Dispatch broker** | D51. `agents-inc dispatch --serve <run-dir>`, started by the CoS outside the sandbox. Reads Lead `inbox/<id>.request.json` (schema 1, inline slots, no paths, env, or credentials; credential-seeking text refused), validates against broker-owned run.json (worker_models, fan_out total, models.json efforts), runs one D47 dispatch under `workers/<id>/`, writes immutable `<id>.report.md` and `<id>.result.json` beside run.json. Workers: scrubbed env, per-Worker TMPDIR; Claude under `sandbox-exec` (home deny list, `~/.claude` secrets denied) or refused. Sequential. Two transports, same validation and 64 KiB request limit. Primary, MCP: `agents-inc run --lead X` starts `mcp_broker.py` as the Lead's stdio MCP server (tools `dispatch`, `status`, `wait`; the server, not the Lead, reads stored results); the Lead has no write grant, cannot read X (Claude Workers cannot either), `wait` answers only IDs the server issued, and the Lead runs under an isolated CODEX_HOME. Fallback, file inbox: Lead gets `agents-inc run --write --run-dir X`: write `X/inbox` only, read X; waits with `dispatch --wait`. |
| **Model pin** | The exact provider slug an alias resolves to, for example sol to gpt-5.6-sol. Explicit, versioned, committed; never floats. Codex aliases only; Claude aliases resolve in the Claude CLI and free providers use floating slugs by design. |
| **Model drift** | A listed, API-supported catalog slug of the same family with a higher version than the pin. Doctor warns MODEL_DRIFT and stays READY. |
| **Bump** | Moving a pin to a newer slug. Operator decides, the CoS runs agents-inc models bump, and a commit records the new pin. Default target is the newest slug; an explicit slug may be named. |
| **Stale install** | An install whose source has committed changes to shipped files since the install was made. Doctor warns INSTALL_STALE and stays READY; the operator runs repair. Uncommitted edits in the source only draw a warning. |
